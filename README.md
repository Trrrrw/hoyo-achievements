# 米游成就

[访问网站](https://ach.trrw.cn) · [源码仓库](https://github.com/Trrrrw/hoyo-achievements)

原神、崩坏：星穹铁道、绝区零成就管理网站，使用 React、Vite 与自定义的冒险手册界面

游戏目录只从 Akasha 读取，不直接访问其他游戏数据来源。个人完成状态和日期保存在当前浏览器，支持 JSON 导入导出、WebDAV、GitHub Gist 和本地文件合并同步，不需要网站账号

目录按游戏缓存在当前页面内存中，切回已加载的游戏不会重复请求，进行中的加载也会被复用。点击“刷新目录”重新获取当前游戏数据；完整目录同时保存到 IndexedDB；断网时可继续使用已加载的游戏目录，个人进度仍保留

多阶段成就按目录中的前置关联合并展示，每个阶段分别保留完成状态、奖励和日期，兼容已有导入导出及 WebDAV 进度文件。全部阶段完成后才归入“已完成”，部分完成仍归入“未完成”；搜索任意阶段的名称、描述或 ID 都会显示完整成就。总进度和分类进度按各阶段计数，清单和分页按合并后的成就计数

## 本地运行

```powershell
bun install --frozen-lockfile
bun run dev
```

访问 `http://127.0.0.1:5176`，开发代理连接 `http://127.0.0.1:7040` 的本地 Akasha

如需连接另一套本地后端，可在启动前设置 `AKASHA_DEV_PROXY`，例如 `$env:AKASHA_DEV_PROXY="http://127.0.0.1:7042"`

生产构建默认连接 `https://akasha.trrw.cn`，可用 `VITE_AKASHA_URL` 指定其他 Akasha 地址，构建时不会包含任何数据写入凭据

```powershell
bun run test
bun run build
```

## UIAF 导入导出

原神支持 [UIGF-Org UIAF 标准](https://uigf.org/zh/standards/uiaf.html)：导入 v1.0 / v1.1，导出 v1.1。点击“导出进度”选择“原神 UIAF v1.1”或“全部游戏备份”；导入自动识别格式，不受当前选择的游戏影响

- UIAF 仅交换原神，每个成就阶段使用原始数字 ID
- v1.1 状态 0 / 1 映射为未完成，2 / 3 映射为已完成；v1.0 没有状态字段，按已完成导入，不推断已领奖
- 保留导入的部分进度、领奖状态和精确时间戳，通过本站备份与 WebDAV 同步仍可保留
- 手动勾选完成导出状态 2；取消完成导出状态 1、进度 0
- 新标记的已完成阶段使用目录目标值作为进度，缺少目标时使用 0
- 时间按 UTC+8 转换；手动日期导出该日零点，未知时间使用标准值 253402271999
- 导入仅更新文件列出的原神记录，保留其他游戏和未列出的记录；文件列出的状态作为本次修改参与后续同步
- 全部游戏备份及 WebDAV 继续使用本站格式，旧文件仍可导入；旧备注仅作为兼容数据保留，不再提供编辑入口

## WebDAV

填写进度文件完整地址，例如 `https://dav.example.com/folder/hoyo-achievements.json`，提前创建目录。文件不存在时自动创建，无需给 Akasha 配置 WebDAV

跨域服务需允许本站来源，支持 `GET`、`PUT`、`OPTIONS`，允许请求头 `Authorization`、`Content-Type`、`If-Match`、`If-None-Match`，并通过 `Access-Control-Expose-Headers: ETag` 暴露强 ETag。不满足这些要求的服务会明确报错，不绕过并发保护

密码只保存在当前页面内存中，刷新后需要重新填写。地址和用户名保存在浏览器；个人进度导出和同步文件不包含 WebDAV 设置或密码

同步按每条成就的更新时间合并，取消完成也保留为新状态，避免旧设备将完成状态恢复。相同时戳使用确定性排序，ETag 冲突最多重试三轮。修改同一条成就时，较新的完整记录获胜；不进行逐字段合并

浏览器数据属于当前站点来源，清理站点数据会清除进度，建议定期导出或同步。第一版每个浏览器维护一份进度，不支持多账号切换

## GitHub Gist 与本地文件

同步弹窗支持三个渠道。GitHub Gist 使用具有 Gist 权限的 Token，可创建秘密 Gist 或同步已有的本站进度 Gist。只持久保存 Gist ID，Token 在关闭弹窗时清除，不进入导出文件或 PWA 缓存

秘密 Gist 不是私密存储，持有链接的人即可读取。同步先读取合并、再写入核对并最多重试三轮；GitHub 不提供本站需要的强条件写入保证，请避免多设备同时操作。已有 Gist 的其他文件不会被修改

本地文件渠道在支持 File System Access 的桌面 Edge / Chrome 中，读取用户所选的本站备份文件、合并进度，再原子关闭写入同一文件。可配合 OneDrive、iCloud 等同步文件夹使用，文件夹跨设备同步由相应客户端负责。损坏文件不会被覆盖；空文件可用于初始化。其他浏览器可使用已有导入、导出功能。不要同时编辑同一个文件

## PWA 与离线使用

支持安装为独立应用，提供 SVG favicon、Apple 图标及普通和 maskable PWA 图标。安装入口位于“同步与备份”弹窗，使用浏览器提供的安装提示；不支持自动提示时显示菜单操作说明

生产构建会生成带内容版本号的 Service Worker，缓存页面与本地静态资源。完整游戏目录另存 IndexedDB，网络中断时显示目录保存日期；从未加载的游戏无法离线初始化。离线勾选与搜索仍可使用，WebDAV / Gist 同步需联网

新版本就绪后在“同步与备份”弹窗显示“刷新更新”，由用户点击后切换，避免自动刷新打断操作。开发模式不注册 Service Worker；用 `bun run build` 后运行 `bunx vite preview --host 127.0.0.1 --port 5177` 验证 PWA。清除站点数据仍会清除本机进度，请定期导出备份

## 数据边界

站点根路径提供 `llms.txt`，介绍功能、数据来源和个人进度边界，并链接使用说明及公开 API 契约。`robots.txt` 允许抓取公开页面；它不控制浏览器本地进度的访问权限

- 读取 `/api/v1/games/{game_id}/achievements` 与 `/achievement-groups`
- 游戏标识为 `ys`、`sr`、`zzz`
- 不把玩家状态发送给 Akasha
- 未确认的隐藏状态、奖励等字段显示为未知或暂无数据，不推测填充
- 目录分页期间检测到数量或分类不一致时要求重新加载

## 本地验收

1. 切换三款游戏，检查目录、分类、名称和描述搜索
2. 勾选成就，打开详情弹窗调整完成日期，刷新后检查完成状态和日期
3. 选择已完成或未完成筛选，导出 JSON 后在另一浏览器导入
4. 配置支持跨域的 WebDAV，在两台设备分别修改不同成就后同步，确认合并结果

提交、推送和发布前先完成本地验收

## 部署

EdgeOne Makers 项目 `hoyo-achievements` 关联本仓库的 `main` 分支，推送后自动部署到 `ach.trrw.cn`。构建预设为 Vite，安装命令为 `bun install`，构建命令为 `bun run build`，输出目录为 `dist`

部署使用公开 Akasha API；浏览器中的个人进度不会随部署迁移。从本地预览迁移到正式域名时，可先导出全部游戏备份，再在正式网站导入
